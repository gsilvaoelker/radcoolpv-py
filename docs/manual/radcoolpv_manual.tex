\section{Purpose and scientific status}

\code{radcoolpv} calculates optical properties of periodic photonic structures
for radiative cooling and couples them to a silicon PV thermal/electrical model.
The active implementation is based on the MATLAB+Lua/S4
\code{matlab-radCoolPV} model. Live optics use only the Stanford S4 Python
extension. S4 is imported lazily; reduced-spectrum and free-form readers can run
without it.

The package reports spectral reflectance \(R\), transmittance \(T\), total
absorptance \(A\), silicon-layer absorptance \(A_{\mathrm{Si}}\), and, under the
conditions stated in Section~\ref{sec:kirchhoff}, emittance. The thermal stage
reports operating temperature, I--V characteristics, maximum-power-point output,
efficiency, and a temperature reduction relative to a user-specified reference.

The library is not a universal PV module model. Its central assumptions are a
periodic coherent optical unit cell, scalar material permittivities, a lumped
steady-state thermal balance, and the silicon diode model inherited from the
MATLAB code. Validation status is evidence-labelled in
Section~\ref{sec:validation}; a passing software test is not treated as proof of
physical validity.

\section{Installation}

\begin{lstlisting}[language=bash]
./install.sh
source .venv/bin/activate
python -c "import radcoolpv; print(radcoolpv.__version__)"
\end{lstlisting}

The thermal/PV stage and spectrum readers use the Python dependencies installed
by \code{install.sh}. Live optics requires a separately compiled S4 Python
module:

\begin{lstlisting}[language=bash]
brew install fftw suite-sparse openblas lapack boost
git clone https://github.com/phoebe-p/S4
cd S4
make -f Makefile.m1 S4_pyext
python -c "import S4; print(S4.__file__)"
\end{lstlisting}

The S4 import occurs only when a case with \code{geometry.source: s4} executes.

\section{Optical model}

\subsection{The S4 problem}

The YAML structure is ordered from the incident medium toward one
semi-infinite terminal layer. S4 expands the in-plane fields in a Fourier basis
of size \code{simulation.s4\_modes}. Flat, circular, rectangular, and
polygonal regions are supplied to S4 analytically; spheres and hemispheres use
the configured stack of circular slices.

At each wavelength, direction, and polarization, the code evaluates the
integrated normal Poynting flux. With incident flux \(P_{\mathrm{inc}}\),

\begin{align}
R &= -\frac{P_{\mathrm{top}}^-}{P_{\mathrm{inc}}},\\
T &= \frac{P_{\mathrm{bottom}}^+}{P_{\mathrm{inc}}},\\
A &= 1-R-T.
\end{align}

Unlike the old Lua output, \(T\) is normalized by incident flux at oblique
incidence. The silicon-layer absorptance uses the net flux at the two interfaces
of the silicon layer itself:

\begin{equation}
A_{\mathrm{Si}} =
\frac{P_{\mathrm{net}}(z_{\mathrm{Si,top}})
      -P_{\mathrm{net}}(z_{\mathrm{Si,bottom}})}
     {P_{\mathrm{inc}}}.
\end{equation}

This prevents absorption in a layer below silicon from being assigned to the
PV cell.

\subsection{Directions and polarization}

One YAML case supports one of three modes:

\begin{itemize}
  \item \code{normal}: \(\theta=0\);
  \item \code{specific}: one user-defined polar angle \(\theta\) and azimuth
        \(\phi\);
  \item \code{hemispherical}: a two-dimensional \((\theta,\phi)\) quadrature.
\end{itemize}

\code{polarization} is \code{TE}, \code{TM}, or \code{unpolarized}. TE and TM
are never assumed equal solely because \(\theta=0\); anisotropic unit cells such
as one-dimensional gratings can give different normal-incidence responses.
Unpolarized output is

\begin{equation}
X_{\mathrm{unpol}}=\frac{X_{\mathrm{TE}}+X_{\mathrm{TM}}}{2},
\qquad X\in\{R,T,A,A_{\mathrm{Si}}\}.
\end{equation}

For one polarization \(p\), the hemispherical property is

\begin{equation}
X_{\mathrm{h},p}(\lambda)=\frac{1}{\pi}
\int_0^{2\pi}\int_0^{\pi/2}
X_p(\lambda,\theta,\phi)\cos\theta\sin\theta
\,d\theta\,d\phi.
\end{equation}

The implementation applies Gauss--Legendre quadrature in
\(u=\sin^2\theta\) and a uniform periodic azimuth rule. It avoids the grazing
endpoint and includes a separate zero-weight normal probe for the PV
luminescence term. Quadrature weights sum to one. A true hemispherical result
therefore requires convergence with respect to both
\code{hemisphere\_theta\_points} and
\code{hemisphere\_azimuth\_points}.

\subsection{Emittance and Kirchhoff's law}
\label{sec:kirchhoff}

The code labels total absorptance as emittance using directional Kirchhoff
reciprocity,

\begin{equation}
\epsilon_p(\lambda,\theta,\phi,T)
=A_p(\lambda,\theta,\phi,T).
\end{equation}

This identification requires a passive reciprocal structure in local thermal
equilibrium, evaluated with the same wavelength, direction, polarization, and
temperature-dependent material state. It is not automatically valid for
nonreciprocal, active, nonlinear, or nonequilibrium emitters. The present
material models are temperature-independent.

\subsection{Materials and numerical validity}

Tabulated models interpolate \(n\) and \(k\) linearly and use
\(\epsilon=(n+ik)^2\). Requests outside a table's wavelength interval raise an
error; endpoint clamping and silent extrapolation are forbidden. Validation E
uses the unmodified refractiveindex.info Olmon evaporated-Au record. Its
SiO2 and Si refractive-index tables are inherited from
\code{matlab-radCoolPV}: the former is labelled Palik/Kitamura; the latter has
no bibliographic source and is made lossless to implement the paper's explicit
nonabsorbing-Si assumption. The current refractiveindex.info database has no
records labelled with the paper-cited Palik/Kitamura Si or SiO2 sources. This
provenance gap is retained as a limitation rather than silently replacing the
models.

Every scientific result must demonstrate:

\begin{enumerate}
  \item passivity and finite \(R,T,A,A_{\mathrm{Si}}\), with
        \(R+T+A\approx1\);
  \item convergence in S4 Fourier basis size;
  \item for hemispherical results, convergence in both angular counts.
\end{enumerate}

\section{Atmosphere, thermal balance, and PV model}

\subsection{Atmospheric and thermal radiation}

For zenith transmittance \(\tau_{\mathrm{atm}}(\lambda)\), the directional
atmospheric emittance is

\begin{equation}
\epsilon_{\mathrm{atm}}(\lambda,\theta)
=1-\tau_{\mathrm{atm}}(\lambda)^{1/\cos\theta}.
\end{equation}

The surface--atmosphere product is integrated with the same angular quadrature
as the surface emittance. With Planck spectral radiance \(B_\lambda(T)\),

\begin{align}
P_{\mathrm{rad}}(T)
 &= \pi\int \epsilon_{\mathrm{h}}(\lambda)B_\lambda(T)\,d\lambda,\\
P_{\mathrm{atm}}(T_{\mathrm{amb}})
 &= \pi\int
 \left\langle\epsilon\epsilon_{\mathrm{atm}}\right\rangle_{\mathrm{h}}
 B_\lambda(T_{\mathrm{amb}})\,d\lambda,\\
P_{\mathrm{conv}}(T)
 &= h\left(T-T_{\mathrm{amb}}\right).
\end{align}

The convection coefficient \(h\) is the total effective nonradiative
coefficient for the reference area used by the balance. It is an external
lumped-model input and is not deduced from geometry or weather data. A
per-surface coefficient must be combined explicitly by the user; the library
does not multiply \(h\) by an assumed number of exposed surfaces.

\subsection{Solar absorption and steady state}

Total absorbed solar power is

\begin{equation}
P_{\mathrm{sun}}=\int A(\lambda)I_{\mathrm{AM1.5G}}(\lambda)\,d\lambda.
\end{equation}

\begin{sloppypar}
For a literature cooling curve that prescribes absorbed solar power directly,
the \code{absorbed\_solar\_power} key in the \code{thermal} section overrides
this integral. Validation E uses the paper value
\(808~\mathrm{W\,m^{-2}}\).
\end{sloppypar}

The cooling-power convention is

\begin{equation}
P_{\mathrm{cool}}(T)=
P_{\mathrm{rad}}-P_{\mathrm{atm}}+P_{\mathrm{conv}}-P_{\mathrm{sun}}
+P_{\mathrm{MPP}}+P_{\mathrm{nt}},
\end{equation}

where \(P_{\mathrm{MPP}}\) is electrical power removed from the cell and
\(P_{\mathrm{nt}}\) is the non-thermal luminescence term. Equilibrium satisfies
\(P_{\mathrm{cool}}(T_{\mathrm{eq}})=0\).

Cooling-curve cases specify their temperature interval in YAML. Standard PV
cases evaluate \(T_{\mathrm{amb}}\) through \(T_{\mathrm{amb}}+150~\mathrm{K}\).
If the balance does not bracket a root, the run raises an error. It never
reports a sweep endpoint as an equilibrium temperature.

\subsection{I--V calculation}

The short-circuit current uses IQE, silicon-layer absorptance, and the solar
photon flux up to the silicon bandgap:

\begin{equation}
J_{\mathrm{sc}}=q\int_0^{\lambda_g}
\mathrm{IQE}(\lambda)A_{\mathrm{Si}}(\lambda)
\Phi_{\mathrm{sun}}(\lambda)\,d\lambda.
\end{equation}

At each \(T,V\), the current density \(J\) solves

\begin{multline}
0=-J+\frac{V-JR_s}{R_{\mathrm{sh}}}
+J_0(T)\left[
\exp\left(\frac{q(V-JR_s)}{k_BT}\right)-1\right]\\
+J_{\mathrm{Auger}}(T,V)-J_{\mathrm{sc}}.
\end{multline}

Output power is \(-JV\). A three-point parabolic refinement gives the MPP
between voltage samples. Open-circuit voltage and operating temperature must be
bracketed; otherwise the calculation fails explicitly.

The bandgap calculation preserves the MATLAB scalar-reduction convention for
parity. This is a model-compatibility choice and should not be confused with a
fully temperature-resolved semiconductor bandgap model.

\subsection{Temperature reduction}

When \code{thermal.reference\_temperature} is supplied,

\begin{equation}
\Delta T_{\mathrm{reduction}}
=T_{\mathrm{reference}}-T_{\mathrm{eq}}.
\end{equation}

The user must define the reference physically, for example the operating
temperature of a bare module under the same boundary conditions. The library
does not invent or silently substitute a reference.

\section{YAML examples}

\subsection{One file with multiple cases}

A top-level \code{cases} list lets one YAML file define several named runs.
The CLI executes them in order:

\begin{lstlisting}
cases:
  - name: normal_TE
    run: {optics: true, thermal: false}
    simulation:
      wavelength: {min: 8.0, max: 13.0, n: 201}
      angles: normal
      polarization: TE
    # geometry, structure, materials, and data follow
  - name: directional_TM
    run: {optics: true, thermal: false}
    simulation:
      wavelength: {min: 8.0, max: 13.0, n: 201}
      angles: specific
      polar_angle_deg: 35.0
      azimuth_angle_deg: 90.0
      polarization: TM
\end{lstlisting}

YAML anchors may hold shared sections. Validation E uses one such file for nine
cases and references digitized text data directly; no helper script is needed.

\subsection{Normal and directional emittance}

\begin{lstlisting}
run:
  optics: true
  thermal: false
  plots: false
  write_outputs: true

simulation:
  wavelength: {min: 8.0, max: 13.0, n: 300}
  angles: specific
  polar_angle_deg: 35.0
  azimuth_angle_deg: 90.0
  polarization: TM
  s4_modes: 80
\end{lstlisting}

For normal incidence, set \code{angles: normal}; the requested TE, TM, or both
are still computed explicitly.

\subsection{Hemispherical emittance}

\begin{lstlisting}
simulation:
  wavelength: {min: 3.0, max: 30.0, n: 1000}
  angles: hemispherical
  polarization: unpolarized
  hemisphere_theta_points: 8
  hemisphere_azimuth_points: 12
  s4_modes: 100
\end{lstlisting}

A live S4 thermal case requires \code{angles: hemispherical}: the energy balance
integrates emissivity over the hemisphere, so a single normal-incidence spectrum
does not define it. Convergence must be checked by increasing the polar-angle
count, azimuth count, and S4 Fourier basis size independently.

That requirement is what makes a live thermal run expensive. The solver cost
scales as
\(n_\lambda \times n_\theta \times n_\phi \times n_{\mathrm{pol}}\):
the listing above is \(1000\) wavelengths over \(8\times12=96\) quadrature
directions, plus one zero-weight normal probe, and an unpolarized case evaluates
both TE and TM at every one of those points. Changing a convection coefficient
or an ambient temperature does not change any of it.

The practical workflow is therefore to run the optics once, write the reduced
spectrum, and re-drive the thermal stage from that file with
\code{run.optics\_results}, which costs no S4 time. Validations A, B, and C are
built this way. Validation C keeps the split explicit: four
\code{optics\_*.yaml} cases call S4 and write \code{data/optics/*.txt}, and two
\code{cell\_*.yaml} cases consume those spectra to solve the energy balance.

To chain the two runs without any intermediate step, set
\code{run.optics\_export} in the optics case to a fixed path and point
\code{run.optics\_results} at that same path in the thermal case. These are the
write and read halves of one five-column format
(\code{lambda\_um R T emit abs\_si}). The export is written even when
\code{run.write\_outputs} is false, because it is requested by explicit path.
Note that \code{optics.csv} cannot be reused here: it is comma-separated with a
text header, which the resume reader rejects, and it lands in a timestamped
folder that a later case cannot name in advance. Case A.1 in
\code{validations/} is the minimal two-command example.

A resumed spectrum retains no directional information. Driving the thermal stage
from a normal-incidence file with \code{run.optics\_results\_angles: normal} is
an explicit angle-independent approximation, not a hemispherical calculation,
and must be reported as such.

\subsection{Layer stack and materials}

\begin{lstlisting}
geometry:
  source: s4
  shape: cylinder
  photonic_material: sio2
  lattice: {type: hexagonal, x: 10.608811, y: 6.125}
  cylinder: {radius: 1.75, height: 2.25}

structure:
  - {material: sio2, thickness: 500.0}
  - {material: silicon, thickness: 500.0}
  - {material: gold, thickness: 0.08}
  - {material: vacuum, thickness: 0.0, terminal: true}

materials:
  sio2: PalikKitamura_SiO2
  silicon: Akerboom_Si_lossless
  gold: RII_Olmon_2012_ev_Au
\end{lstlisting}

Exactly one terminal layer is required, it must be last, and its thickness must
be zero because S4 treats it as semi-infinite.

\subsection{Thermal case and temperature reduction}

\begin{lstlisting}
thermal:
  ambient_temperature: 300.0
  # Calibrated effective total coefficient; the paper states 6.0.
  convection_coefficient: 12.54
  absorbed_solar_power: 808.0
  reference_temperature: 360.0
  cooling_temperature: {min: 260.0, max: 380.0, n: 121}
  equilibrium: auto
\end{lstlisting}

For a digitized table whose first column is wavelength and later columns are
different measured emittances, set
\code{run.optics\_results\_emittance\_column} to the desired zero-based column.
Column zero is reserved for wavelength.

\section{Outputs and reproducibility}

MATLAB-style output compatibility has been removed. New runs write:

\begin{itemize}
  \item \code{optics.csv}: selected directional or hemispherical spectrum;
  \item \code{optics\_directional.csv}: every S4 wavelength, polar angle,
        azimuth, polarization, angular weight, \(R,T,A,A_{\mathrm{Si}}\);
  \item \code{iv.csv}, \code{power.csv}, or \code{cooling\_power.csv};
  \item \code{run.json}: full resolved configuration, Git revision, dirty flag,
        interpreter/platform, S4 binary hash, input paths and SHA-256 hashes,
        and scalar results;
  \item figures when \code{run.plots: true}.
\end{itemize}

Set \code{run.write\_outputs: false} for tests or programmatic validation.
Historical MATLAB files remain only as read-only parity fixtures and under the
gitignored \code{archive/}; they are never emitted by the active package.

\section{Required verification for new cases}

For every new publication or device case:

\begin{enumerate}
  \item place all geometry, materials, directions, polarization, wavelength,
        and numerical settings in YAML;
  \item record source data and reject unavailable parameters rather than
        inventing them;
  \item verify \(R+T+A\), passivity, material wavelength coverage, and
        layer-resolved absorption;
  \item demonstrate wavelength, Fourier-mode, polar-angle, and azimuth
        convergence as applicable;
  \item distinguish unit tests, MATLAB parity, independent optical validation,
        literature reproduction, digitized comparison, and calibrated fit;
  \item compare published and calculated values with absolute or relative
        errors and retain unresolved failures.
\end{enumerate}
